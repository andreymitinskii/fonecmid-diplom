# Доработка конфигурации «Управление IT-фирмой» для компании «Ваш компьютерный мастер»

Дипломный проект по профессии «1С-программист: с нуля до middle».
Текст исходного задания — в [репозитории Нетологии](https://github.com/netology-code/fonecmid-diplom)
и в каталоге [tasks](tasks) этого репозитория.

Доработка добавляет две подсистемы — **работа с заявками клиентов** и **расчёт
управленческой зарплаты**, четыре отчёта, печатную форму акта и интеграцию
с телеграм-ботом.

---

## Инструкция по начальной настройке

Инструкция описывает действия в информационной базе, где **уже ведётся учёт**,
чтобы начать пользоваться новой функциональностью. Все шаги выполняет
пользователь с профилем «Администратор».

### Шаг 1. Обновление конфигурации

Загрузите доработанную конфигурацию и выполните обновление конфигурации базы
данных. Новые объекты добавляются, существующие данные не изменяются.

### Шаг 2. Заполнение констант

Раздел «Обслуживание клиентов» → «Константы». Заполните четыре константы:

| Константа | Чем заполнить |
|---|---|
| Номенклатура «Абонентская плата» | Элемент справочника «Номенклатура», которым в актах отражается ежемесячная абонентская плата |
| Номенклатура «Работы специалиста» | Элемент справочника «Номенклатура» для выполненных работ |
| Токен телеграм-бота | Токен, выданный BotFather |
| Идентификатор группы телеграм | Идентификатор группы, куда бот шлёт оповещения |

Первые две обязательны: без них не работают автозаполнение реализации и массовое
создание актов. Константы телеграма можно оставить пустыми — тогда оповещения
не отправляются, остальное работает.

### Шаг 3. Создание телеграм-бота (если нужны оповещения)

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, задайте имя
   и идентификатор бота, скопируйте токен в константу.
2. Создайте группу, добавьте в неё бота и назначьте боту права администратора.
3. Напишите в группу любое сообщение и откройте в браузере
   `https://api.telegram.org/bot<ВашТокен>/getUpdates`. Найдите в ответе
   идентификатор группы (отрицательное число) и внесите его в константу.

### Шаг 4. Включение регламентного задания

«Администрирование» → «Обслуживание» → «Регламентные и фоновые задания».
Включите задание **«Отправка уведомлений телеграм-боту»** и задайте расписание,
например каждые 5 минут.

Задание обходит очередь уведомлений, отправляет сообщения и удаляет отправленные.
Если отправка не удалась, сообщение остаётся в очереди до следующего запуска,
а причина пишется в журнал регистрации.

### Шаг 5. Заполнение производственного календаря

«Управленческая зарплата» → «График работы». Внесите записи на расчётный период:
одна запись на каждый **рабочий** день со значением 1.

Календарь используется при расчёте оклада по отработанным дням и среднедневного
заработка для отпускных. Без него оклад начислен не будет.

### Шаг 6. Заполнение справочника сотрудников

«Управленческая зарплата» → «Сотрудники». Для каждого укажите категорию —
**Специалист** или **Административный персонал** — и свяжите с пользователем базы.

Категория определяет состав начислений: специалистам дополнительно начисляется
процент от выполненных работ. В календарь загрузки попадают только специалисты.

### Шаг 7. Условия оплаты сотрудников

«Управленческая зарплата» → «Условия оплаты сотрудников». Внесите записи
с указанием месяца, с которого они действуют: оклад и процент от работ.

Запись обязательна для каждого специалиста, которого будут указывать
в обслуживании клиента: **без записи документ не проводится**. Нулевой процент —
допустимое значение, проверяется наличие записи, а не её значение.

### Шаг 8. Настройка договоров

В справочнике «Договоры контрагентов» для абонентских клиентов создайте договоры
с видом **«Абонентское обслуживание»** и заполните появившиеся поля: период
действия договора, сумму ежемесячной абонентской платы, стоимость часа работы.

Обслуживание клиента проводится только по договору этого вида и только если дата
документа попадает в период его действия.

### Шаг 9. Назначение прав пользователям

«Администрирование» → «Настройки пользователей и прав» → «Профили групп доступа».
В поставке добавлены четыре профиля:

| Профиль | Кому назначать | Что даёт |
|---|---|---|
| Специалист | Инженерам | Ввод и проведение обслуживания, календарь загрузки, отчёт по выработке |
| Менеджер | Менеджерам по работе с клиентами | То же плюс ведение контрагентов |
| Бухгалтер ИТ-фирмы | Бухгалтеру | Массовое создание актов, печать акта, отчёт по выставленным актам |
| Кадровик-расчётчик | Расчётчику зарплаты | Условия оплаты, расчёт и выплата зарплаты, график отпусков, отчёты по зарплате и отпускам |

Создайте группы доступа на основе этих профилей и включите в них пользователей.

### Шаг 10. Календарь загрузки на начальной странице

Календарь доступен в разделе «Обслуживание клиентов». Чтобы вывести его
на начальную страницу: «Конфигурация» → «Открыть рабочую область начальной
страницы» → добавить форму обработки **«Календарь специалистов»**.

Это единственный шаг настройки, выполняемый в конфигураторе.

## Порядок работы

1. Менеджер планирует обслуживание: создаёт документ с клиентом, договором,
   специалистом, датой и плановым временем. При записи в очередь попадает
   уведомление телеграм-боту.
2. Специалист после работ заполняет табличную часть выполненных работ,
   прикладывает скан листа учёта и проводит документ.
3. В начале месяца бухгалтер запускает **«Массовое создание актов»**: обработка
   находит действующие абонентские договоры, создаёт и проводит реализации,
   пропуская те, по которым акт за месяц уже есть.
4. Кадровик-расчётчик вводит **«Начисление заработной платы»** за месяц: оклад,
   отпускные, процент специалистов от работ и НДФЛ рассчитываются автоматически.
5. Выплата вводится документом **«Выплата зарплаты»** с автозаполнением
   по остаткам задолженности.

## Принятые решения, о которых стоит знать

**Префикс `ВКМ_`** проставлен на всех добавленных объектах и на реквизитах,
добавленных в типовые объекты. Внутри собственных `ВКМ_`-объектов реквизиты
префикса не несут: объект уже помечен, дублирование ухудшало бы читаемость.
Изменения в типовых модулях выделены комментариями `// ВКМ_ Начало`
и `// ВКМ_ Конец`.

**Макет печатной формы** назван `ПФ_MXL_ВКМ_АктОбОказанныхУслугах`: префикс
`ПФ_MXL_` обязателен по требованиям БСП, иначе не работает редактирование макета
пользователем, которое требуется в задании.

**Регистр «Выполненные клиенту работы» сделан оборотным**, хотя в задании назван
регистром сумм задолженности. Расход по нему не формирует ни один документ,
поэтому остатки росли бы бесконечно и задолженностью не являлись бы. И
автозаполнение реализации, и отчёт по актам используют обороты за месяц.

**Добавлены два регистра сверх явного перечня задания.** Отчёты по условиям
задания обязаны строиться только по регистрам, поэтому:

- `ВКМ_ЗапланированныеОтпуска` — иначе план отпусков остался бы только
  в документе и отчёт о расходе отпусков строить было бы не из чего;
- `ВКМ_ВыставленныеРаботы` — типовая реализация в этой конфигурации не пишет
  ни в один регистр с номенклатурой (в «Продажи» пишет только заказ покупателя),
  поэтому фактически выставленные суммы взять было неоткуда.

**НДФЛ каждый документ удерживает со своих начислений.** Расчёт по всей базе
периода регистрации привёл бы к повторному удержанию налога с одной суммы, если
за месяц введены и начисление зарплаты, и премия.

**Метод автозаполнения реализации** назван `ВКМ_ВыполнитьАвтозаполнение`: общее
требование о префиксе для добавляемых методов имеет приоритет над именем,
упомянутым в тексте задания.

**Замечание проверки конфигурации о реквизите «Комментарий»** документа
обслуживания воспроизводит поведение всех пяти типовых документов конфигурации,
где этот реквизит объявлен точно так же.
