# Автоматизированное тестирование

Сценарий проверяет подсистему «Работа с заявками клиентов» целиком — от
планирования заявки менеджером до сверки отчёта с эталоном.

Файл сценария: [features/ВКМ_РаботаСЗаявкамиКлиентов.feature](features/ВКМ_РаботаСЗаявкамиКлиентов.feature)

## Что проверяет сценарий

| Сценарий | От чьего имени | Что проверяется |
|---|---|---|
| Планирование обслуживаний | Менеджер | Создание двух заявок с указанием специалиста, даты и планового времени |
| Закрытие обслуживаний | Специалист | Заполнение выполненных работ и проведение документов |
| Массовое создание актов | Бухгалтер | Обработка находит договор, создаёт и проводит реализацию |
| Анализ выставленных актов | Бухгалтер | Отчёт формируется и совпадает с ожидаемыми суммами |

Проверяемые суммы не случайны: две заявки дают 2 + 3 = 5 часов к оплате,
при ставке часа 1000 ₽ по договору автотеста это 5 000 ₽. Столько же должно
попасть в акт, поэтому в отчёте колонки «Должно быть выставлено» и «Фактически
выставлено» обязаны совпасть. Расхождение означает поломку в цепочке
«обслуживание → регистр → автозаполнение реализации → регистр выставленных работ».

## Что нужно для запуска

1. **Платформа 1С:Предприятие 8.3.27** и информационная база с доработанной
   конфигурацией. Подойдёт демонстрационная база из раздела Releases.
2. **Vanessa Automation** — скачайте с
   [официального репозитория](https://pr-mex.github.io/vanessa-automation/dev/)
   внешнюю обработку `VanessaAutomation.epf`.
3. В базе должен быть **включён режим отладки** и разрешено подключение
   тестируемого приложения: «Конфигурация» → «Параметры» → «Запуск 1С:Предприятия» →
   «Дополнительные» → флаг «Устанавливать режим управляемого приложения».

## Подготовка базы

Сценарий не создаёт справочные данные сам — он работает с заранее заведёнными
элементами. Перед первым запуском в базе должны быть:

| Объект | Значение |
|---|---|
| Контрагент | `Автотест Клиент` |
| Договор контрагента | `Автотест Договор`, вид «Абонентское обслуживание», период действия включает март 2026, абонплата 15 000 ₽, стоимость часа 1 000 ₽ |
| Сотрудник | `Автотест Специалист`, категория «Специалист» |
| Условия оплаты | Для `Автотест Специалист` на март 2026: оклад 50 000 ₽, процент от работ 20 |
| Номенклатура | Два элемента для констант «Абонентская плата» и «Работы специалиста» |
| Константы | Обе номенклатурные константы заполнены |

В демонстрационной базе из раздела Releases эти данные уже заведены.

## Пользователи

Сценарий переключается между тремя сеансами, поэтому в базе нужны три
пользователя с соответствующими профилями групп доступа. В демонстрационной базе
это следующие пользователи:

| Имя клиента в сценарии | Логин пользователя | Полное имя | Профиль |
|---|---|---|---|
| `Менеджер` | `Менеджер` | Менеджер по работе с клиентами | Менеджер |
| `Специалист` | `Специалист` | Автотест Специалист | Специалист |
| `Бухгалтер` | `Бухгалтер` | Морозова Анна | Бухгалтер ИТ-фирмы |

Кроме них в базе есть `Администратор` с профилем «Администратор»
и `КадровикРасчетчик` (Никитина Ольга) с профилем «Кадровик-расчётчик» —
они в сценарии не участвуют.

Имя клиента — это метка в настройках Vanessa, она не обязана совпадать с именем
пользователя базы; соответствие задаётся на вкладке «Настройка клиентов
тестирования». В своей базе можно использовать любых пользователей с этими
профилями, изменив соответствие в настройках, а не в тексте сценария.

Пароли должны быть пустыми либо указаны в настройках клиентов Vanessa.

## Настройка клиентов Vanessa

Сценарий использует три именованных тестовых клиента: `Менеджер`, `Специалист`,
`Бухгалтер`. Их нужно один раз описать в настройках Vanessa Automation:

1. Откройте `VanessaAutomation.epf` в базе.
2. Вкладка **«Настройка клиентов тестирования»** → добавьте три строки.
3. Для каждой укажите имя клиента (ровно как в таблице выше), путь к базе
   и имя пользователя, под которым открывается сеанс.

Именно эти имена подставляются в шаг
`Я запускаю сценарий открытия TestClient или подключаю уже существующий "..."`.

## Запуск

1. Откройте `VanessaAutomation.epf` в информационной базе.
2. На вкладке **«Сценарии»** нажмите «Открыть каталог» и укажите каталог
   `tests/features` этого репозитория.
3. Нажмите **«Выполнить сценарии»**.

Отчёт о выполнении Vanessa покажет по каждому шагу результат; при падении
сохраняется скриншот и текст ошибки.

### Запуск из командной строки

```
"C:\Program Files (x86)\1cv8\8.3.27.1936\bin\1cv8.exe" ENTERPRISE ^
  /F "<путь к базе>" ^
  /N "Администратор" ^
  /Execute "<путь>\VanessaAutomation.epf" ^
  /C "StartFeaturePlayer;VBParams=<путь>\vaParams.json"
```

Файл `vaParams.json` формируется в самой Vanessa кнопкой «Сохранить параметры»
после того, как настроены каталог сценариев и клиенты тестирования.

## Результат прогона

Сценарий прогнан дважды: на копии демонстрационной базы и на **пустой базе**,
созданной с нуля из конфигурации. Оба раза пять сценариев, ноль падений,
ноль ошибок (отчёт jUnit, около пяти минут).

На пустой базе тест создал все данные сам: заявки получили первые номера
(000000001 и 000000002), реализация — 000000001 на 20 000 рублей.

Прогон повторяем: первый сценарий создаёт организацию, номенклатуру,
константы, клиента, договор, специалиста и условия оплаты, а также удаляет
документы предыдущего прогона за тестовый месяц. Поэтому его можно запускать
и на пустой базе, и многократно на одной и той же.

## Запуск на пустой базе

Прикладных данных тест не требует, но пользователи, под которыми подключаются
клиенты тестирования, должны существовать. Порядок подготовки:

1. Создать файловую базу и загрузить в неё конфигурацию.
2. Создать пользователя `Администратор` с ролями «Полные права»
   и «Администратор системы».
3. Войти администратором: библиотека стандартных подсистем выполнит
   обновление информационной базы и создаст поставляемые профили групп доступа.
4. Создать пользователей `Менеджер`, `Специалист`, `Бухгалтер`, создать группы
   доступа по одноимённым профилям и включить в них этих пользователей.
5. Связать элементы справочника «Пользователи» с пользователями информационной
   базы и пересчитать роли.

Шаг 5 обязателен и делается **только с признаком `ОбменДанными.Загрузка`**:

```bsl
Объект = Ссылка.ПолучитьОбъект();
Объект.ОбменДанными.Загрузка = Истина;
Объект.ИдентификаторПользователяИБ = ПользовательИБ.УникальныйИдентификатор;
Объект.Записать();
УправлениеДоступом.ОбновитьРолиПользователей();
```

Без этого признака библиотека не принимает ссылку на пользователя
информационной базы: группы доступа заполнены, профили содержат роли,
а у пользователя ролей нет и вход заканчивается сообщением
«Нет прав на запуск требуемого вида клиента».

## Грабли запуска

**Лицензия разработчика ограничивает число клиентов информационной базы.**
Менеджер тестирования сам занимает одно подключение, поэтому все сценарии
закрывают сеанс клиента тестирования последним шагом
(`я закрываю сеанс текущего клиента тестирования`). Без этого второй и третий
клиенты не входят: «Превышено ограничение лицензии для разработчиков
на количество клиентов информационной базы».

**Перед прогоном войдите в базу администратором.** После обновления
конфигурации библиотека стандартных подсистем выполняет обновление
информационной базы. Пока оно не выполнено, клиенты тестирования встречают
окно «В данный момент вход в приложение невозможен».

**Ссылочные поля заполняются через кнопку выбора,** а не вводом текста:
открывается список справочника, нужная строка ищется в таблице и выбирается.
