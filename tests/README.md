# Автоматизированное тестирование

Сценарий проверяет подсистему «Работа с заявками клиентов» целиком: от
планирования заявки менеджером до сверки отчёта с ожидаемыми суммами.

Файл сценария:
[features/ВКМ_РаботаСЗаявкамиКлиентов.feature](features/ВКМ_РаботаСЗаявкамиКлиентов.feature)

## Что проверяется

| Сценарий | От чьего имени | Что делает |
|---|---|---|
| Подготовка данных | Менеджер | Создаёт всё, что нужно для теста, и убирает результаты прошлого прогона |
| Планирование обслуживаний | Менеджер | Создаёт две заявки с указанием специалиста, даты и времени |
| Закрытие обслуживаний | Специалист | Заполняет выполненные работы и проводит документы |
| Массовое создание актов | Бухгалтер | Обработка находит договор, создаёт и проводит реализацию |
| Анализ выставленных актов | Бухгалтер | Отчёт формируется и сходится с ожидаемыми суммами |

Суммы в последнем сценарии взяты не с потолка. Две заявки дают 2 + 3 = 5 часов
к оплате, при ставке 1000 ₽ это 5000 ₽. Столько же должно попасть в акт,
поэтому в отчёте «Должно быть выставлено» и «Фактически выставлено» обязаны
совпасть. Если они разошлись, значит сломалось что-то в цепочке
«обслуживание → регистр → автозаполнение реализации → регистр выставленных
работ».

## Что нужно для запуска

1. Платформа 1С:Предприятие 8.3.27 и база с доработанной конфигурацией.
   Подойдёт демонстрационная база из раздела Releases.
2. Vanessa Automation — внешняя обработка `VanessaAutomation.epf`
   с [сайта проекта](https://pr-mex.github.io/vanessa-automation/dev/).
3. В базе должен быть разрешён режим отладки и подключение тестируемого
   приложения.

## Подготовка данных

Отдельно готовить данные не нужно: первый сценарий создаёт организацию,
номенклатуру, константы, клиента, договор, специалиста и условия оплаты. Если
что-то из этого уже есть, повторно не создаётся.

Он же удаляет заявки и акты за тестовый месяц, оставшиеся от прошлого прогона,
поэтому сценарий можно запускать сколько угодно раз подряд.

Данные, с которыми работает тест:

| Объект | Значение |
|---|---|
| Контрагент | ООО «Ромашка» |
| Договор | «Абонентское обслуживание АО-2026/07», абонплата 15 000 ₽, час работы 1000 ₽ |
| Специалист | Соловьев Максим |
| Период теста | ноябрь 2026 |

## Пользователи

Сценарий работает от имени трёх пользователей, поэтому они должны быть
в базе вместе с профилями групп доступа:

| Имя клиента в Vanessa | Пользователь базы | Профиль |
|---|---|---|
| `Менеджер` | `Менеджер` | Менеджер |
| `Специалист` | `Специалист` | Специалист |
| `Бухгалтер` | `Бухгалтер` | Бухгалтер ИТ-фирмы |

Имя клиента тестирования — это метка в настройках Vanessa, она не обязана
совпадать с именем пользователя базы. Соответствие задаётся на вкладке
«Настройка клиентов тестирования», так что в своей базе можно взять других
пользователей с теми же профилями, не меняя текст сценария.

Пароли должны быть пустыми либо указаны в настройках клиентов.

## Запуск

1. Открыть `VanessaAutomation.epf` в базе.
2. На вкладке «Настройка клиентов тестирования» описать три клиента из таблицы
   выше: имя, путь к базе и пользователя.
3. На вкладке «Сценарии» нажать «Открыть каталог» и указать каталог
   `tests/features` этого репозитория.
4. Нажать «Выполнить сценарии».

### Из командной строки

```
"C:\Program Files (x86)\1cv8\8.3.27.1936\bin\1cv8.exe" ENTERPRISE ^
  /F "<путь к базе>" ^
  /N "Администратор" ^
  /Execute "<путь>\VanessaAutomation.epf" ^
  /C "StartFeaturePlayer;VBParams=<путь>\vaParams.json"
```

Файл `vaParams.json` сохраняется из самой Vanessa кнопкой «Сохранить
параметры» после того, как настроены каталог сценариев и клиенты тестирования.

## Результат прогона

Сценарий прогонялся на базе, развёрнутой из демонстрационного `.dt`
из раздела Releases, и на пустой базе, созданной с нуля из конфигурации.
Оба раза пять сценариев, ноль падений и ноль ошибок по отчёту jUnit.

На демонстрационной базе прогон занял около семи минут:

| Сценарий | Время |
|---|---|
| Подготовка данных | 42 с |
| Планирование обслуживаний | 53 с |
| Закрытие обслуживаний | 155 с |
| Массовое создание актов | 64 с |
| Анализ выставленных актов | 99 с |

На пустой базе тест создал все данные сам: заявки получили номера 000000001
и 000000002, реализация — 000000001 на 20 000 ₽.

## Запуск на пустой базе

Прикладные данные тест создаёт сам, но пользователи должны существовать
заранее. Порядок такой:

1. Создать файловую базу и загрузить конфигурацию.
2. Создать пользователя `Администратор` с ролями «Полные права»
   и «Администратор системы».
3. Войти администратором, чтобы БСП выполнила обновление информационной базы
   и создала поставляемые профили групп доступа.
4. Создать пользователей `Менеджер`, `Специалист`, `Бухгалтер`, создать группы
   доступа по одноимённым профилям и включить в них этих пользователей.
5. Связать элементы справочника «Пользователи» с пользователями базы
   и пересчитать роли.

Шаг 5 работает только с признаком `ОбменДанными.Загрузка`:

```bsl
Объект = Ссылка.ПолучитьОбъект();
Объект.ОбменДанными.Загрузка = Истина;
Объект.ИдентификаторПользователяИБ = ПользовательИБ.УникальныйИдентификатор;
Объект.Записать();
УправлениеДоступом.ОбновитьРолиПользователей();
```

Без этого признака библиотека не принимает ссылку на пользователя базы:
группы доступа заполнены, в профилях есть роли, а у пользователя ролей нет,
и вход заканчивается сообщением «Нет прав на запуск требуемого вида клиента».

## Что учесть при запуске

**Лицензия разработчика ограничивает число клиентов базы.** Менеджер
тестирования сам занимает одно подключение, поэтому каждый сценарий последним
шагом закрывает сеанс клиента (`я закрываю сеанс текущего клиента
тестирования`). Больше одного клиента тестирования одновременно не работает,
и во время прогона к базе не должно быть подключено ничего постороннего —
ни конфигуратора, ни второго окна программы, ни COM-соединения.

Аварийно закрытый сеанс (например, если процесс 1С сняли через диспетчер
задач) какое-то время продолжает числиться подключённым и держит лицензию.
После такого клиенты тестирования перестают подключаться по таймауту: помогает
заново развернуть базу из `.dt`.

**Если база развёрнута из `.dt`,** при первом входе библиотека спрашивает,
перемещено приложение или это копия. Пока вопрос не отвечен, работа
с внешними ресурсами заблокирована. Ответить нужно до прогона, иначе окно
вопроса перехватит управление у клиента тестирования.

**Перед прогоном нужно зайти в базу администратором.** После обновления
конфигурации БСП выполняет обновление информационной базы, и пока оно
не прошло, клиенты тестирования встречает окно «В данный момент вход
в приложение невозможен».

**Ссылочные поля заполняются через кнопку выбора,** а не вводом текста:
открывается список справочника, там ищется нужная строка и выбирается.
